# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this repo is

This repository is the skill. The shipped artifact is `SKILL.md` (plus `AGENTS.md` for Codex) and the supporting `reviewers/`, `gates/`, `scripts/`, `templates/`, `ci-integrations/`, `docs/`, and `hosts/` trees. See [Installation](README.md#install) for host paths, detection, refresh, and stale-link recovery.

Practical consequence: most "code" here is Markdown that another LLM reads as instructions. Edits to `SKILL.md`, `reviewers/*.md`, `gates/pr-scope.md`, `docs/*.md`, and `templates/*.md` change runtime behavior of the skill the same way a code change would. Treat them as code.

## Commands

```bash
bash tests/run.sh                 # full bats suite + SKILL.md drift guard (matcher-rule prose lives only in docs/synthesis.md)
bats tests/bats/<file>.bats       # single test file
ruff check . && ruff format --check .   # Python lint/format (scripts/*.py, target py312, line length 100)
python scripts/validate_metadata.py     # checks SKILL.md frontmatter (name/version/description + semver) and that templates/state.schema.json is valid JSON Schema
scripts/regen.sh         # regenerate persona-derived surfaces (cog + regen_schema_enum.py)
scripts/regen-check.sh         # --check companion; CI gate, exits 5 on drift
./install.sh [--cursor|--claude|--codex|--opencode|--uninstall]
```

The `personas.yaml ↔ filesystem ↔ schema` invariants are not checked by `validate_metadata.py`; they are enforced by the bats sync tests (via `scripts/personas_manifest.py`) and by `scripts/regen-check.sh`.

`tests/run.sh` requires `bats-core >= 1.7`, `jq`, `git`, and `python3` with `pyyaml` + `jsonschema`. Older Ubuntu `bats` 1.2.x is rejected by the script.

CI (`.github/workflows/ci.yml`) runs: shellcheck, markdownlint (config in `.markdownlint.json`), `validate_metadata.py`, ruff, the bats suite, and an install-smoke test. The toolchain is Markdown, Bash, and Python.

The skill itself runs inside a host LLM session, so there is no `run-the-skill` command from this repo's perspective. To exercise it manually, install it into a host and ask the host to use it on a PR.

## High-level architecture

The runtime contract is `SKILL.md` Steps 1–5. The most non-obvious aspects:

- **`reviewers/personas.yaml` is the source of truth for the panel.** Multiple surfaces are now generator-managed and regenerated by `scripts/regen.sh`: the SKILL.md "Reviewer personas" bullet list (via `cog`), the SKILL.md §4b Move A/A.1/B/C bullets (via `cog`, from the `move_*` flags), the `reviewer` enum in `reviewers/output.schema.json` (via `scripts/regen_schema_enum.py`), and panel-count phrases inside `<!-- regen:panel-count-* -->` regions across `SKILL.md`, `tests/scenarios/*.md`, and `reviewers/*.md` (via `scripts/regen_panel_counts.py`, which also enforces a corpus-wide `--validate-coverage` closure scan against unwrapped numbered persona-count phrases). `scripts/regen-check.sh` is the `--check` companion and is wired into CI (`validate` job, exits 5 on drift). Other surfaces (the on-disk `reviewers/*.md` file set, the Move C drift guards, per-persona prose tuned per domain) remain manual; `tests/bats/test_skill_moves_persona_sync.bats` pins the move flags against the `## Procedure move` headings on disk and are still enforced by bats sync tests; when changing personas, run `scripts/regen.sh` first, then `bash tests/run.sh`; any remaining failing tests name the still-manual surfaces. See `docs/editing-personas.md`.
- **`manifests/dev-trees.yaml` is the source of truth for the dev-only trees every consumer skips.** `scripts/regen_dev_trees.py` writes four surfaces from it, each in its own syntax: `CURSOR_INSTALL_SKIP_NAMES` (`install.sh`), `CAP_GREP_EXCLUDES` (`tests/run.sh`), `copy_skill_tree`'s rsync excludes (`tests/bats/test_helper.bash`), and the leading `_GREP_EXCLUDES` entries (`scripts/regen_move_a1_enum.py`). Content-specific excludes (`docs/superpowers`, `tools/recall-harness/*`, `tests/scenarios/`) mean different things per consumer and stay local. See `docs/change-map.md`.
- **Three promotion paths, one owner.** `scripts/promote_findings.py` is the only place that promotes a `suggestion` to `blocker`. The three paths are: (a) adversary endorsement of a panel suggestion via the §4c matcher; (b) multi-source: `suggestion_promotion_threshold` distinct reviewers surface the same finding; (c) evidence-gated solo-adversary. The matcher rule (same file, ±5 lines, Jaccard token overlap ≥ 0.6 with English stopword filtering) lives canonically in `docs/synthesis.md` and `scripts/match_findings.py`. **`tests/run.sh` has a drift guard that fails if the matcher rule (a `token_overlap >= 0.6` line) ever appears in `SKILL.md`**; keep it in `docs/synthesis.md` only. The promotion threshold (`suggestion_promotion_threshold`) is a knob and *does* appear in `SKILL.md`; the guard only polices the matcher rule itself.
- **Procedure moves A/A.1/B/C.** Move A (test-intent audit), Move A.1 (assertion-vacuity audit, with a closed `move_a1_pattern` 5-value enum), and Move B (second-instance sweep) wording is inlined per persona because it's tuned per domain; which personas carry each move is declared by the `move_a`/`move_a1`/`move_b`/`move_c` flags in `reviewers/personas.yaml` and rendered into the SKILL.md §4b bullets by cog. Move C (cross-doc consistency) body lives canonically in `docs/procedure-moves.md` and `move_c: true` personas link to it; severity rules ("terminology drift = blocker; contract drift = suggestion; schema-constraint = suggestion owned by `type_design`") live in that doc. A `move_c` drift guard bats test pins canary phrases, and a separate Move A.1 drift guard pins the persona↔schema↔SKILL.md↔state-mirror enum.
- **Reviewers share the orchestrator's checkout.** The loop operates in place (`SKILL.md` Step 2) and §4b spawns the panel in parallel, so every reviewer reads the same tree the §4e edit phase is writing to. The no-mutation rules live in `reviewers/_working_tree_addendum.md`, linked from every panel persona and the adversary; `tests/bats/test_addendum_link_sync.bats` pins that delivery. Adding a shared addendum means three manual steps (file, `personas.yaml` `addendums:`, a link section per persona) because nothing concatenates them. See `docs/change-map.md`.
- **Gated personas early-exit above their severity rules.** `yagni` returns `verdict: approve` with empty findings unless the diff adds a surface its gate lists; `blind_spots` does the same, but only when its two procedure-move conjuncts also hold (see below). Either gate sits above the `## What to flag as` sections, so a rule naming an unlisted surface is silently unreachable. Severity bullets on both cite the gate surface id(s) that admit them (`- (c) ...`, or `- (b)(c)(d) ...` when a rule spans surfaces), pinned by `tests/bats/test_gate_rule_reachability.bats`. `type_design`'s gate is one condition rather than a surface list, so it restates the gate in its blocker section instead. A gated persona carrying procedure moves must also name the independently triggered ones as conjuncts its gate does not override, or the gate and the moves instruct different outputs on one diff. Move B needs no conjunct: it fires only after a finding exists, so it cannot reach the early-exit path. `requirements` has done this for Move C all along; `blind_spots` was the one that had not, and now names Move A and Move C (`tests/bats/test_applicability_gate_text.bats`). See `docs/editing-personas.md`.
- **Adversary is not a panel persona.** It runs separately in `SKILL.md` §4d.0 after the panel synthesizes, on the approval path and (capped per loop; see `docs/adversary.md`) on the shallow-review forced path. It uses `reviewers/output.schema.json` with `reviewer: "adversary"` but is not in `personas.yaml` `panel:`. Its mechanics are in `docs/adversary.md`.
- **State is ephemeral, off-tree.** Loop state lives at `<git-dir>/pr-loop/state.json` (`git rev-parse --git-dir`), never tracked. Shape is canonical in `templates/state.schema.json`. Reviewer JSON is transient; only synthesized partitions persist to `history[]`.
- **Reviewer evaluation.** See [Evaluating reviewer changes](docs/editing-personas.md#evaluating-reviewer-changes); harness usage lives in [tools/recall-harness/README.md](tools/recall-harness/README.md).
- **Loop exit conditions are executable.** `scripts/check_exit_conditions.py` owns the `NO_PROGRESS` and `CI_STUCK` comparisons that used to live only in SKILL.md prose; `SKILL.md` §4d/§4d.1 invoke it and link to `docs/exit-conditions.md`. Blocker matching is `finding_matcher.is_match_or_summary`: the §4c rule plus a normalized-summary fallback for findings missing `file` or `line`, which `is_match` mishandles (a missing `line` is rejected; two missing `file` values compare equal). Don't reimplement either rule in prose.
- **Two layers of tests.** `tests/bats/` covers deterministic plumbing (shell scripts, sync invariants, drift guards). `tests/scenarios/*.md` are manual pressure-test fixtures used to TDD the skill's discipline under approval/scope/sunk-cost pressure; see `tests/README.md` for the RED/GREEN/REFACTOR protocol. `tests/scenarios/manifest.yaml` is the source of truth for each scenario's validation tier (`ci_trusted` / `manual_validated` / `design_only`), and `tests/bats/test_scenario_validation_sync.bats` enforces a different evidence contract per tier: proof-source paths that exist and are cited, a dated PASS marker, or a `**Missing evidence:**` line. Most scenarios are still `design_only`; those needing a recorded host run cannot be closed by writing a test.

## Editing rules specific to this repo

- **Helper scripts over inlined logic in `SKILL.md`.** When the skill needs to do something procedural (write a metric, fetch comments, count LOC, run local validation, push safely, sync the skill install), extract it into `scripts/` and have `SKILL.md` invoke it. Startup sync: `scripts/sync_skill.sh`; see `docs/skill-update.md`. `SKILL.md` length is bats-pinned (`test_skill_md_length.bats`, current cap 390 lines; currently 389) precisely to force this discipline; most edits that add prose will fail the cap.
- **Don't restate cross-surface rules in `SKILL.md`.** The matcher rule, Move C body, and synthesis mechanics live in `docs/*.md`; `SKILL.md` paraphrases and links. Drift guards in `tests/run.sh` and `tests/bats/test_move_c_drift_guard.bats` enforce this.
- **Reviewer JSON is canonical via `reviewers/output.schema.json`.** `evidence` (top-level, shallow-review detection) is distinct from `finding_evidence` (per-finding, fuels the §4d.0.5 solo-adversary path). Don't conflate them.
